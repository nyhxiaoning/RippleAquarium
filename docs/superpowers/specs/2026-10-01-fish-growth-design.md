# 鱼类成长档案系统设计

## 1. 背景与目标

RippleAquarium 当前通过 `FishState` 保存鱼的位置、速度和运动状态，通过鱼种目录与鱼群句柄管理数量，但没有稳定的个体身份、成长数据或游戏存档。珊瑚已有一次性的入场生长动画，该逻辑不适合作为鱼类长期成长系统复用。

本阶段只实现鱼类个体成长档案，目标是：

- 每个生物个体拥有跨刷新稳定的 ID。
- 记录出生时间、累计年龄、成长阶段、成长进度和体型倍率。
- 鱼在游戏运行时成长，离线后再次进入可补算成长，单次最多补算 24 小时。
- 从幼体到成体累计需要 2 小时，并通过连续缩放表现成长。
- 自动保存成长记录，并能处理损坏数据和未来的数据结构升级。
- 为后续天气影响成长预留倍率接口，但本阶段不实现天气、饥饿、健康、寿命、死亡或繁殖。

## 2. 范围

### 2.1 本阶段包含

- 沙丁鱼、锦鲤、小丑鱼和当前目录中的海星均建立独立成长档案。
- 成长阶段分为幼体、成长期和成体。
- 单鱼记录与按鱼种汇总的成长界面。
- 自动保存、导出成长记录和带确认的重置成长记录。
- 鱼缸样式切换、数量增减和模型热替换时保留成长状态。
- 纯逻辑单元测试、存档往返测试和管理器集成测试。

### 2.2 本阶段不包含

- 新增鱼种或其他海洋生物。
- 天气及其视觉效果。
- 饥饿、健康、水质、寿命、死亡、繁殖和食物链。
- 云端同步、用户账号或服务端存档。
- 对现有 boids 行为规则进行大规模重构。

## 3. 方案选择

采用独立成长档案系统，而不是把所有成长和存档逻辑塞入 `FishState`，也不把项目重构为完整实体组件系统。

成长领域层不依赖 Three.js。鱼群模拟继续负责位置、速度和行为，只通过稳定 ID 取得当前体型倍率。这样可保持现有渲染和 boids 架构，同时让天气、水质等未来系统通过明确接口影响成长速度。

## 4. 数据模型

新增 `src/growth/` 目录，包含以下核心类型：

```ts
type FishGrowthStage = "juvenile" | "growing" | "adult";

interface FishGrowthRecord {
  fishId: string;
  speciesId: string;
  bornAt: number;
  accumulatedAgeSeconds: number;
  lastUpdatedAt: number;
  stage: FishGrowthStage;
  growthProgress: number;
  sizeMultiplier: number;
  active: boolean;
}

interface FishGrowthSnapshot {
  schemaVersion: 1;
  savedAt: number;
  records: FishGrowthRecord[];
}
```

`bornAt` 和 `lastUpdatedAt` 使用 Unix 毫秒时间戳；`accumulatedAgeSeconds` 是成长判定的权威数值。`stage`、`growthProgress` 和 `sizeMultiplier` 是便于显示与导出的派生值，加载时重新计算并覆盖，避免缓存值与年龄不一致。

每个鱼种在成长配置中声明幼体尺寸和成体尺寸。第一版所有鱼种共用成长时间：

- 幼体：0 至 20 分钟。
- 成长期：20 至 80 分钟。
- 成体：80 至 120 分钟。
- 120 分钟后保持成体尺寸。

这里的“成体”是阶段名称：个体在 80 分钟进入成体阶段，并继续缓慢增长，到 120 分钟达到完全成熟尺寸。默认幼体尺寸为完全成熟尺寸的 55%。20 至 120 分钟之间使用平滑插值增长到 100%。鱼种可以覆盖幼体尺寸范围，海星使用适合海底生物的单独尺寸范围。

## 5. 模块边界

### 5.1 `growth/types.ts`

只定义可序列化类型、阶段枚举和成长配置类型，不引用 DOM 或 Three.js。

### 5.2 `growth/registry.ts`

`FishGrowthRegistry` 负责：

- 创建稳定 ID 和单鱼档案。
- 按鱼种激活、停用和恢复档案。
- 根据模拟时间推进在线年龄。
- 应用受上限保护的离线补算。
- 使用纯函数计算阶段、进度和尺寸。
- 提供单鱼查询、鱼种汇总和全量快照。
- 接收预留的 `growthRateMultiplier`，默认值为 1。

注册表不直接读写浏览器存储，也不操作渲染对象。

### 5.3 `growth/storage.ts`

存档模块负责：

- 使用独立的 `localStorage` 键保存版本化快照。
- 严格校验 JSON 结构、有限数值、合法阶段和唯一 ID。
- 提供按 `schemaVersion` 分派的迁移入口。
- 存档损坏时保留原始字符串到带时间戳的备份键，再回退为空存档。
- 捕获配额、安全策略和隐私模式导致的存储异常。
- 支持将成长记录导出为下载 JSON。

存储失败不得中断模拟；界面显示失败状态并允许稍后重试。

### 5.4 鱼群与渲染适配

`FishState` 增加 `fishId`，但不承担年龄计算或持久化。创建和调整鱼群时，管理器从注册表取得与数量匹配的稳定 ID，再传给对应鱼群。

实例化渲染在计算实例矩阵时叠加单鱼 `sizeMultiplier`。小丑鱼和海星当前没有暴露统一的个体状态，需要扩展 `SchoolHandle`，提供稳定 ID 绑定与实例级尺寸更新。高细节模型加载后重建鱼网格时，必须复用原有 ID，而不能创建新档案。

## 6. 个体生命周期

### 6.1 新增数量

先恢复同鱼种被停用的档案，按停用时间从近到远选择；仍不足时才创建新档案。这样用户短暂调低数量再调高时不会无故失去成熟个体。

### 6.2 减少数量

优先停用最年轻的个体，不删除档案。停用个体不累计在线成长，但再次加载时仍参与统一的离线补算，因为离线期间无法区分鱼缸数量调整发生的具体时刻。

### 6.3 切换鱼缸样式

按新样式的每个鱼种目标数量执行同样的激活或停用规则。仍存在的同种个体保留 ID、年龄和阶段。新样式未包含的鱼种全部停用。

### 6.4 重置成长记录

重置属于独立操作，需要二次确认。确认后删除当前快照与损坏存档备份，并按当前鱼缸配置为活跃生物重新创建档案。切换样式和项目现有的“重置样式”按钮不得重置成长记录。

## 7. 时间与成长流程

### 7.1 启动

1. 读取并校验最新成长快照。
2. 用当前时间减去 `savedAt` 得到离线时长，限制在 0 至 24 小时。
3. 将离线时长加入所有已有档案，随后重算派生字段。
4. 将档案与当前鱼缸描述合并，使各鱼种活跃数量与场景配置一致。
5. 创建鱼群并把稳定 ID、尺寸倍率绑定到渲染实例。

系统时钟倒退时离线时长按 0 处理。异常大的时钟跳变仍受 24 小时上限保护。

### 7.2 运行

只有正常播放中的模拟时间会增加在线年龄。暂停期间不增长；单步调试仅按实际推进的固定步长增长。成长注册表每次模拟更新都可接收 `dt`，但仅在档案数据变脏后触发后续自动保存。

天气系统未来可以在调用注册表更新时提供 `growthRateMultiplier`。快照只保存实际累积后的年龄，不需要保存历史天气。

### 7.3 自动保存

- 数据变脏后最多每 10 秒保存一次。
- `visibilitychange` 进入隐藏状态和 `pagehide` 时立即尝试保存。
- 不依赖 `beforeunload` 完成异步工作。
- 保存成功、保存中、保存失败和未保存变更均有可读状态。

## 8. 用户界面

在现有右侧控制面板新增“鱼类成长”区域：

- 总览：活跃总数、幼体数、成长期数量、成体数和保存状态。
- 鱼种汇总：名称、活跃数量、各阶段数量和平均成长进度。
- 单鱼列表：短 ID、累计年龄、阶段、成长百分比和当前尺寸。
- 操作：导出成长记录、重置成长记录。

鱼种汇总默认展示，单鱼列表按鱼种折叠，避免数百个实例同时生成 DOM。第一版不允许直接编辑年龄，也不增加成长粒子或光效。

中英文文案加入现有 `i18n.ts` 字典。阶段名称、时间和保存错误均提供双语文本。

## 9. 错误处理

- 记录缺字段、数值无穷、ID 重复或鱼种非法时，整个快照判定无效，备份后回退，不静默接受部分损坏状态。
- 单次渲染未找到成长档案时使用尺寸倍率 1，并记录开发环境警告，保证画面继续运行。
- `localStorage` 不可用时在内存中继续成长，界面持续显示“无法保存”。
- 导出失败时不修改当前档案。
- 所有数量输入继续受到现有鱼种最大数量约束；注册表不得创建超过目标活跃数量的实例。

## 10. 测试策略

### 10.1 纯逻辑测试

- 20、80、120 分钟边界的阶段判定。
- 55% 到 100% 的连续、单调尺寸插值。
- 非法 `dt`、时钟倒退和 24 小时离线补算上限。
- 成长倍率接口对累计年龄的影响。

### 10.2 生命周期测试

- 增加数量先恢复停用档案，再创建新档案。
- 减少数量优先停用最年轻个体。
- 切换样式后同种个体 ID 和年龄不变。
- 模型刷新后 ID 与体型倍率不变。
- 暂停不增长，单步只增长一个固定步长。

### 10.3 存档测试

- 保存和加载往返一致。
- 派生字段在加载时依据年龄重算。
- 损坏 JSON、缺字段、重复 ID 和未来版本均安全回退。
- 存储写入异常不会中断成长更新。

### 10.4 回归与性能

- 保持现有 `aquarium-manager` 和 boids 测试通过。
- 为管理器增加成长注册表集成测试。
- 对默认场景及目录最大数量进行帧时间检查。
- 成长面板折叠时不创建单鱼列表 DOM；展开时只渲染所选鱼种。

## 11. 验收标准

- 刷新页面后，每个现有个体的 ID、年龄和阶段保持不变。
- 离线 30 分钟后再次进入，年龄约增加 30 分钟；离线超过 24 小时最多增加 24 小时。
- 新鱼从约 55% 体型开始，在累计 2 小时内平滑成长为成体。
- 暂停一分钟不会增加鱼龄。
- 调低再调高某鱼种数量时，优先恢复原有个体。
- 切换预设不会重置已有同种鱼的成长。
- 存档损坏或浏览器禁止存储时，游戏仍可正常运行并显示可理解的状态。
- 导出的 JSON 能反映当前所有活跃和停用档案。
- `npm test`、`npm run typecheck` 和 `npm run build` 全部通过。

## 12. 后续阶段接口

本阶段只为后续系统保留以下接口，不提前实现其玩法：

- 天气系统向成长更新提供 `growthRateMultiplier`。
- 鱼种目录可扩展每种鱼的成长尺寸配置和模型资源。
- 生物多样性系统复用稳定个体 ID、档案汇总和存档版本机制。

新增鱼种、天气变化和更丰富的海洋生物应分别形成后续设计与实现计划，避免把生态模拟一次性耦合进本阶段。
