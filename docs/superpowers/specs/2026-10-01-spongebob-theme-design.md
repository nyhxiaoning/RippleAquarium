# 海绵宝宝主题内容设计

## 1. 背景与目标

RippleAquarium 当前已有菠萝屋和海绵宝宝/派大星底部装饰，并拥有天气、程序化鱼类、海洋生态生物、动态栖息地和可切换鱼缸预设。本阶段增加章鱼哥、蟹老板及其主题场景内容，使默认鱼缸形成完整的海绵宝宝主题角落，同时为后续点击互动、台词和小游戏保留接口。

本阶段只实现程序化低多边形角色、主题道具和低幅度待机动画，不引入新的外部模型或远程资源，不实现对话、任务、收集品或小游戏。

## 2. 范围

### 2.1 包含

- 程序化章鱼哥角色 `squidward`。
- 程序化蟹老板角色 `mr-krabs`。
- 章鱼哥房屋/复活节岛头像风格道具 `squidward-house`。
- 蟹堡王风格招牌/柜台道具 `krusty-krab`。
- 章鱼哥触手摆动和蟹老板钳子开合待机动画。
- 默认、珊瑚礁、深海、小缸四个预设的主题内容配置。
- 主题显示/隐藏、道具显示/隐藏、动画开关和缩放控制。
- 碰撞障碍和小丑鱼避让区域接入。
- 中英文名称、错误降级、资源释放和自动化测试。

### 2.2 不包含

- 外部下载 GLB、贴图或音频资源。
- 角色点击、台词、任务、收集品或小游戏的实际玩法。
- 角色成长、健康、鱼群行为或天气核心逻辑重构。
- 新增独立的主题存档；主题配置不写入鱼类成长快照。

## 3. 设计原则

- 新增独立 `src/theme/` 模块，避免继续把主题逻辑堆进 `scene-builder.ts`。
- 主题角色使用共享低多边形几何、共享材质和简单层级组，遵循现有静态资源低开销策略。
- 角色和道具通过现有场景生命周期加入、更新、缩放和销毁。
- 主题更新不修改鱼类成长存档格式；后续交互功能通过事件接口扩展。
- 小缸预设优先保证鱼和生态生物的可见空间，必要时自动缩放或隐藏大型道具。
- 程序化创建失败时使用基础几何或隐藏单个对象，不阻塞主场景。

## 4. 模块结构

### 4.1 `src/theme/types.ts`

定义主题类型和生命周期接口：

```ts
type ThemeCharacterId = "squidward" | "mr-krabs";
type ThemePropId = "squidward-house" | "krusty-krab";

interface ThemeObjectHandle {
  group: THREE.Group;
  update(time: number, dt: number): void;
  resize(halfSize: THREE.Vector3): void;
  dispose(): void;
}
```

角色句柄额外暴露 `setAnimationEnabled(enabled: boolean)` 和 `getInteractionAnchor(): THREE.Object3D`，为后续点击事件和台词挂点提供稳定位置。

### 4.2 `src/theme/characters.ts`

提供 `createThemeCharacter(id, options): ThemeObjectHandle`：

- 章鱼哥：灰蓝色头部和身体、紫色触手吸盘、简化五官。
- 蟹老板：红色身体、蓝色衣物、黄色眼睛和两只钳子。

模型使用几何组合而非外部网格。角色的身体、眼睛、触手/钳子分别保留引用，动画模块只修改旋转和局部位置，不重建几何。

### 4.3 `src/theme/props.ts`

提供 `createThemeProp(id, options): ThemeObjectHandle`：

- `squidward-house`：复活节岛头像轮廓和简化门窗。
- `krusty-krab`：小型餐厅招牌、柜台和旗帜。

道具句柄提供碰撞半径、障碍形状和小丑鱼避让区域，交由场景构建器合并到现有障碍与排除区。

### 4.4 `src/theme/animation.ts`

提供无分配的时间驱动动画函数：

- `updateSquidwardAnimation(parts, time, enabled)`：低频触手摆动和身体轻微左右晃动。
- `updateMrKrabsAnimation(parts, time, enabled)`：左右钳子交替开合、身体轻微前倾。
- 动画关闭时恢复静态姿态，不改变角色位置或存档。

### 4.5 `src/theme/catalog.ts`

保存主题目录、中英文名称、默认缩放、默认位置、预设启用状态和小缸降级规则。场景构建器只消费目录配置，不硬编码角色分支。

## 5. 角色与道具表现

### 5.1 章鱼哥区域

- 默认放置在鱼缸左后侧或珊瑚礁边缘。
- 角色主色灰蓝，触手使用紫色吸盘点缀。
- 章鱼哥房屋/头像道具放在角色附近的底部区域。
- 角色固定在底部，不参与鱼群 boids。
- 角色和房屋作为障碍，鱼群绕行，小丑鱼仍可接近珊瑚和海葵。
- 触手以低幅度正弦运动摆动，身体缓慢左右晃动。

### 5.2 蟹老板区域

- 默认放置在鱼缸右后侧或底部开阔区域。
- 角色主色红色，衣物蓝色，眼睛黄色。
- 蟹堡王道具由招牌、柜台和小旗帜组成。
- 角色固定在底部，角色道具形成小型障碍区，不堵住鱼群主通道。
- 两只钳子交替开合，身体偶尔轻微前倾。

### 5.3 尺寸与天气

- 角色高度控制在鱼缸高度的 15%–22%。
- 晴朗、阴天、降雨和暴风雨只改变环境光和阴影，角色颜色保持可识别。
- 主题角色不受天气影响而消失；天气只可通过预留的动画倍率接口轻微改变摆动幅度。

## 6. 预设配置

### 默认鱼缸

启用章鱼哥、蟹老板和两处主题道具，保持左右两侧构图；角色与道具使用标准尺寸。

### 珊瑚礁

保留两个角色，主题道具缩小约 15%，为珊瑚、海葵和鱼类留出更多空间。

### 深海

保留两个角色和道具，降低材质亮度并使用深色主题光照；动画速度降低，保持深海氛围。

### 小缸

角色缩小到标准尺寸的 65%–75%，主题道具默认隐藏或仅保留招牌/小型头像。尺寸不足时优先隐藏道具，角色仍可显示。

所有预设均可由控制面板单独关闭角色、道具或动画。

## 7. 场景与碰撞集成

`AquariumDescriptor.decor` 的 `asset` 联合类型扩展为包含主题角色和道具。`scene-builder.ts` 在构建时：

1. 从主题目录读取启用对象和位置。
2. 创建角色和道具并加入根节点。
3. 将道具障碍合并到现有 boids 障碍列表。
4. 将主题避让区合并到小丑鱼排除区。
5. 每帧调用角色和道具 `update(time, dt)`。
6. resize 时按新 halfSize 限制位置和缩放。
7. dispose 时释放所有主题对象资源。

主题对象不能改变现有鱼群稳定 ID、成长注册表、天气状态或生态生物数量。

## 8. 控制面板与未来接口

新增“海绵宝宝主题”控制区：

- 章鱼哥显示/隐藏。
- 蟹老板显示/隐藏。
- 章鱼哥房屋显示/隐藏。
- 蟹堡王招牌/柜台显示/隐藏。
- 主题动画开关。
- 主题缩放控制。

主题状态存放在运行时主题配置中，不写入鱼类成长存档。为后续趣味功能预留：

- 角色点击事件。
- 当前动画状态和角色交互锚点。
- 台词/提示语触发接口。
- 主题收集品挂点。
- 小游戏或任务触发点。
- 天气对角色动画幅度的倍率输入。

## 9. 错误处理与性能

- 程序化角色创建失败时回退到基础几何角色。
- 道具创建失败时只跳过该道具，不影响场景初始化。
- 动画异常时保留静态模型并停止该对象动画。
- 小缸空间不足时自动缩放角色或隐藏道具。
- 所有几何和材质在销毁时释放，重复 `dispose` 不得抛错。
- 角色和道具尽可能共享材质/几何，动画只更新已有对象的变换。
- 不在每帧创建数组、颜色或 Three.js 临时对象。
- 主题对象数量固定且很少，不得降低鱼群、天气或生态核心更新频率。

## 10. 测试策略

### 10.1 主题模型

- 两个角色和两个道具都能创建，拥有非空层级和材质。
- 动画开启时对应部件会改变，关闭后姿态稳定。
- 角色和道具可以重复销毁且不会泄漏资源。
- 创建失败时回退或跳过行为可验证。

### 10.2 场景与预设

- 四个预设的主题启用状态、位置、缩放和小缸降级规则正确。
- 默认、珊瑚礁、深海和小缸场景均能构建。
- 主题障碍和避让区不会让鱼群越界或阻挡主要通道。
- 切换预设、resize、模型刷新后不产生重复角色。

### 10.3 UI 与回归

- 主题显示/隐藏、道具显示/隐藏、动画开关和缩放控制会立即生效。
- 中英文主题文案正确切换。
- 主题同时启用天气、成长、鱼群和生态系统时不改变已有存档。
- `npm test`、`npm run typecheck`、`npm run build` 全部通过。

## 11. 验收标准

- 默认页面能看到章鱼哥、蟹老板及各自主题场景。
- 章鱼哥触手和蟹老板钳子持续低幅度待机动画。
- 角色和道具不漂浮、不穿透鱼缸边界，不阻塞主要鱼群通道。
- 小缸中主题内容不会导致严重拥挤。
- 关闭主题对象后不会影响鱼类、天气、成长和生态系统。
- 主题模块资源在预设切换后正确释放。
- 后续可在不改场景构建器核心流程的情况下接入点击、台词或小游戏。

## 12. 后续趣味扩展边界

本阶段只交付视觉主题和待机动画。后续可在独立设计中增加角色点击反馈、随机台词、宝藏收集、主题任务、天气反应事件或轻量小游戏；这些功能应复用本阶段的角色事件、动画状态和交互锚点接口。
